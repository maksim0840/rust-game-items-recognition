# Распознавание игровых предметов Rust по иконкам

**99.83% top-1 accuracy** на 1211 классах предметов (13629 реальных изображений в тестовой выборке).

## Задача

Определять название предмета по изображению ячейки инвентаря. Сложность: около 1200 классов, иконки почти не меняются, но лежат на произвольном игровом фоне и перекрыты элементами интерфейса.

## Подготовка данных

### Определение положения ячеек

Прежде чем распознавать предмет, его нужно вырезать из скриншота. Интерфейс сундука в Rust зависит от двух параметров — разрешения экрана и настройки UI scale, — поэтому положение ячеек не фиксировано.

Вместо обучения детектора координаты были получены аналитически. Замеры на разных разрешениях и масштабах показали, что интерфейс задан **в долях экрана**: после деления координат на ширину или высоту точки с разных разрешений совпадают, а сама доля линейно зависит от scale. Отсюда формула:

```
координата = размер_экрана · (a · scale + k)
```

Коэффициенты `a` и `k` находятся линейной регрессией по замерам.

Сетка ячеек оказалась равномерной — наблюдаемые расхождения в ±1 пиксель между соседними ячейками объясняются округлением дробной разметки, а не реальной неравномерностью. Благодаря этому вся геометрия описывается шестью числами: начало сетки, шаг и размер ячейки по каждой из осей. Каждое из них подчиняется той же формуле, что и координаты рамки, поэтому 12 коэффициентов позволяют вычислить положение любой ячейки при любом разрешении и масштабе с точностью до пикселя.

### Источники данных

**Обучающий набор** строится из иконок предметов, извлечённых напрямую из файлов игры. Это оригинальные изображения с прозрачным фоном — эталонный вид каждого предмета.

**Валидационный и тестовый наборы** собраны из реальных скриншотов игры и размечены вручную. Такое разделение принципиально: обучаться можно на синтетических данных, но оценивать качество нужно только на настоящих, иначе измеряется работа генератора, а не модели.

### Генератор обучающих данных

Иконка из файлов игры сама по себе не похожа на то, что видно в игре. Поэтому был написан генератор, собирающий реалистичное изображение ячейки из компонентов:

1. **Фон** — случайный фрагмент, вырезанный из игрового скриншота.
2. **Затемнение** — поверх фона накладывается полупрозрачная рамка инвентаря. Её цвет и прозрачность были измерены по парам скриншотов «инвентарь открыт / закрыт»; выяснилось, что смешение происходит в линейном световом пространстве, а не в sRGB.
3. **Предмет** — иконка вписывается в отведённую область с учётом прозрачности.
4. **Дополнительные элементы** — полоска прочности, текстовая информация, квадраты модификаторов. Каждый накладывается случайно и не у всех предметов.
5. **Изменение размера** — итоговое изображение приводится к формату, который принимает модель.

Все параметры выбираются заново при каждом обращении, поэтому изображения не повторяются между эпохами обучения. Важное условие: пул фонов и набор оверлеев **общие для всех предметов** — иначе модель могла бы связать конкретный фон с конкретным классом и начать угадывать по окружению, а не по самому предмету.

### Обнаруженные проблемы в данных

**Предметы без иконок.** Часть предметов в файлах игры не имеет собственного изображения. Такие записи были исключены из набора — обучать модель распознавать то, чего не существует визуально, невозможно.

**Дублирующиеся иконки.** Более серьёзная проблема: некоторые иконки используются сразу для нескольких предметов. Изначально они считались разными классами, то есть модель просили различить визуально идентичные картинки — задача неразрешимая в принципе.

После объединения таких предметов в один класс количество классов сократилось до 1211, а точность выросла с 98.5% до 99.9%. Это означает, что большая часть прежних ошибок была вызвана не качеством модели, а противоречием в разметке.


## Модель

### Принцип работы

Для решения задачи выбран подход, при котором модель не выдаёт название предмета напрямую, а переводит изображение в вектор — набор чисел, описывающий содержимое картинки. Векторы похожих изображений оказываются близко друг к другу, разных — далеко.

Распознавание строится в три шага:

1. Для каждого предмета вычисляется **центроид** — усреднённый вектор всех его изображений, эталон класса.
2. Новая картинка переводится в вектор.
3. Измеряется расстояние от этого вектора до центроидов всех предметов — побеждает ближайший.

**Почему не был выбран обычный классификатор:** Классификатор жёстко привязан к списку классов: при добавлении нового предмета в игру модель пришлось бы переобучать целиком. При работе через центроиды достаточно вычислить эталонный вектор нового предмета и добавить его в список — сама модель остаётся неизменной.

### Выбор архитектуры

В качестве модели, переводящей изображение в вектор, взята **ConvNeXt-Tiny**, предобученная на наборе ImageNet. Причины выбора:

- устойчивость к небольшим размерам батча;
- хорошая работа с мелкими объектами (в сравнении с ViT-архитектурами);
- простота дообучения.

### Метод обучения

Чтобы дообучить модель под наши предметы, сверху временно добавляется классификатор с функцией потерь **ArcFace**. Он оценивает, насколько правильно модель разложила векторы — близко ли расположены изображения одного предмета и достаточно ли далеко разные предметы, — и по этой оценке корректирует веса модели.

ArcFace нужен **только на время обучения**. После его завершения классификатор отбрасывается, и в работе используется только сама модель и построенные по ней центроиды.

### Две фазы обучения

Само обучение происходит в 2 фазы:

**Фаза 1.** ConvNeXt-Tiny полностью заморожен, обучаются только новые слои — проекция и голова ArcFace. Это необходимо потому, что случайно инициализированные слои на старте выдают хаотичные градиенты, способные повредить качественные предобученные признаки модели.

**Фаза 2.** После того как новые слои настроились, модель размораживается и дообучается вместе с ними, но с пониженным learning rate: её веса уже хорошие, их требуется лишь слегка адаптировать под игровые иконки, а не переучивать заново.


## Результаты

Сравнивались пять конфигураций, каждая из которых отличалась от базовой одним параметром: величиной margin, scale, learning rate backbone и оптимизатором. Наилучшие результаты показала **baseline** модель с классическим набором параметров (`s=30, m=0.5`, AdamW, `lr_backbone=1e-5`). Остальные конфигурации отличались от неё в пределах статистического шума, за исключением SGD, уступившего по всем метрикам.

### Метрики

| метрика | валидация | тест | что означает |
|---|---|---|---|
| **top-1 accuracy** | 99.92% | **99.83%** | доля предметов, распознанных верно с первой попытки |
| **top-5 accuracy** | 100% | **99.99%** | доля случаев, когда правильный предмет попал в пятёрку ближайших центроидов |
| **separation** | 0.916 | **0.915** | насколько вектор ближе к своему центроиду, чем к чужим — показатель надёжности разделения классов |
| **ошибок** | — | **23 из 13629** | 0.17% тестовой выборки |

Близость валидационных и тестовых метрик подтверждает, что модель не переобучилась под валидацию и честно обобщается на невиданные данные.

Из 23 ошибок правильный предмет в 21 случае всё равно оказался среди пяти ближайших центроидов — то есть модель почти никогда не ошибается грубо. Оставшиеся ошибки приходятся на визуально похожие предметы и на изображения низкого качества при малом UI scale.

### Порог уверенности

Для отказа от ответа в неопределённых случаях введён порог близости к ближайшему центроиду — **0.73**. Если ближайший центроид оказался дальше этого значения, система не выдаёт название предмета, а сообщает, что не уверена в распознавании.

Порог нужен прежде всего для ситуаций, которых не было в обучении: предметы, добавленные в игру после обучения модели, частично перекрытые иконки, посторонние элементы интерфейса. Без него модель в таких случаях всё равно выдала бы ближайший по вектору класс, причём с виду уверенно.

Значение 0.73 полностью отсекает посторонние изображения, задерживает 15 из 23 ошибочных предсказаний и стоит 2.1% покрытия. Повышать порог дальше невыгодно: после 0.76 число задержанных ошибок перестаёт расти, тогда как потери верных ответов продолжают увеличиваться.


## Использование модели

### Скачивание

Модель доступна на Hugging Face: **[ссылка будет добавлена]**

Пакет состоит из пяти файлов:

| файл | назначение |
|---|---|
| `item_recognizer.onnx` | модель, переводящая изображение в вектор |
| `centroids.npy` | матрица эталонных векторов `[1211, 256]` в формате NumPy |
| `centroids.pt` | та же матрица в формате PyTorch |
| `items_meta.json` | соответствие «индекс класса → название предмета» |
| `preprocess.json` | параметры подготовки изображения и порог уверенности |

Центроиды продублированы в двух форматах. `centroids.npy` не требует установленного PyTorch и читается на любой платформе, включая C# и C++ — этот вариант предназначен для развёртывания вместе с ONNX-моделью. `centroids.pt` удобен, если работа ведётся в PyTorch-окружении.

### Требования к входному изображению

На вход подаётся кроп одной ячейки инвентаря:

- формат **RGB** (альфа-канал отбрасывается);
- размер приводится к **224×224**;
- значения пикселей делятся на 255 (диапазон `[0, 1]`), **без дополнительной нормализации**;
- порядок осей `[batch, channels, height, width]`.

### Загрузка и инференс

```python
import json, numpy as np, onnxruntime as ort
from PIL import Image

session = ort.InferenceSession("item_recognizer.onnx",
                               providers=['CPUExecutionProvider'])
centroids = np.load("centroids.npy")          # [1211, 256], нормализованы
# либо, в PyTorch-окружении:
# centroids = torch.load("centroids.pt").numpy()
items_meta = json.load(open("items_meta.json"))
cfg = json.load(open("preprocess.json"))


def preprocess(image):
    img = Image.open(image) if isinstance(image, str) else image
    img = img.convert('RGB').resize(tuple(cfg["input_size"]), Image.BILINEAR)
    arr = np.asarray(img, dtype=np.float32) / 255.0     # [H, W, C] -> [0,1]
    return arr.transpose(2, 0, 1)[np.newaxis, ...]      # -> [1, C, H, W]


def predict(image):
    """Возвращает (название, уверенность). Название = None, если модель не уверена."""
    emb = session.run(None, {'image': preprocess(image)})[0]   # [1, 256]

    sims = (emb @ centroids.T)[0]        # близость к каждому центроиду
    idx = int(sims.argmax())
    conf = float(sims[idx])

    if conf < cfg["threshold"]:
        return None, conf
    return items_meta[str(idx)]["name"], conf
```

### Как считается класс

Модель возвращает **уже нормализованный** вектор, центроиды тоже нормализованы, поэтому их скалярное произведение сразу даёт косинусную близость. Класс определяется индексом максимального значения, а само значение служит мерой уверенности. Если оно ниже порога **0.73**, модель отказывается от ответа.

### Обработка нескольких ячеек

Модель принимает переменный размер батча — все ячейки сундука выгоднее прогонять за один вызов:

```python
def predict_batch(images):
    batch = np.concatenate([preprocess(im) for im in images], axis=0)
    embs = session.run(None, {'image': batch})[0]
    sims = embs @ centroids.T
    idxs, confs = sims.argmax(axis=1), sims.max(axis=1)
    return [(items_meta[str(int(i))]["name"] if c >= cfg["threshold"] else None, float(c))
            for i, c in zip(idxs, confs)]
```

### Добавление новых предметов

Модель не привязана к списку классов. Чтобы добавить предмет, появившийся в игре после обучения, достаточно прогнать его изображения через модель, усреднить полученные векторы, нормализовать результат и дописать новую строку в `centroids.npy` вместе с записью в `items_meta.json`. Переобучение не требуется.
